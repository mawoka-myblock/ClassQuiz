## 3. Bugs found by the visual pass

### 3.1 The editor can drop an edit silently *(not fixed — your call)*

`frontend/src/lib/editor.svelte:128` takes the "nothing has changed yet" baseline
**500ms after the editor opens**:

```js
setTimeout(() => (saved_snapshot = JSON.stringify(data)), 500);
```

Type inside that half-second and the baseline is taken *over your edit*, so `unsaved` is
false, `flush()` returns without sending anything, and `saveQuiz()` still navigates to the
quiz page as if it had saved. The change is gone, with a "Saved" indicator and no error.

It reproduces: `e2e/account.e2e.ts` "a signed-in owner can reopen a quiz in the editor and
save a change" failed 1 run in 3 for exactly this reason. It is the only failing test in
the suite and it is not a flake in the test, it is a flake in the product.

The 500ms exists because the rich-text fields normalise their content on load, which would
otherwise show as an unsaved change. The cheap fix is to take the baseline immediately and
accept one harmless no-op save per session; the careful fix is to set the late baseline only
if nothing has been typed since load. Either is a few lines, but it is the save path, so it
is not something to change without both of you knowing.

### 3.2 Three strings printed their own key *(fixed, pushed)*

i18next dropped the `_plural` suffix in v20; this repo is on 25, where it is `_one` / `_other`.
Three call sites still asked for `_plural`, and i18next prints the key when it misses:

- **host lobby**, with two or more players: `2 play_page.players_waiting_plural` — on the projector, in front of the room
- **host per-question results**: the same key beside every answer count
- **My Quizzes**: `2 words.question_plural` on every card with more than one question

The `_one` / `_other` keys were already in `en.json`. Fixed in this branch.

### 3.3 There is no frog green anywhere

`app.css` sets `--primary: oklch(0.21 0.006 285.885)` — shadcn's zinc default. Every primary
control in the app is black in light mode and near-white in dark. `components.json` has no
`theme` key either. `CLAUDE.md` says theme `green` "is what makes `--primary` the frog green";
that is not true of the current tree, so either the preset was lost in a re-apply or the doc
was always aspirational. Either way the brand colour exists only in the rainbow wordmark.

Not a bug, but it is the single cheapest change to make the product look like itself, and
somebody should decide before you show it around.
