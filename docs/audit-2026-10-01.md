### Anonymous storage, verified

`localStorage['frogquiz_anon_secrets']` holds `{quiz_id: secret}`; the quiz itself lives on
the server. Clearing it loses edit/start/delete, not the quiz. The 30-day sweep is an **arq
worker cron** (`frogquiz/worker/storage.py`, 03:00 daily, `worker` service in
`docker-compose.yml`). Nothing verifies that container is running in production — if it is
not, the promise in the copy is not kept.

## 3. Findings

### 3.1 The editor can drop an edit silently *(not fixed — your call)*

`lib/editor.svelte:128` takes the "nothing changed yet" baseline **500ms after the editor
opens**. Type inside that half-second and the baseline is taken over your edit, so `unsaved`
is false, `flush()` sends nothing, and Save still navigates to the quiz page as if it had
saved. Reproduced 1 run in 3 (`account.e2e.ts`, the only failing test). The 500ms exists
because the rich-text fields normalise on load. Cheap fix: take the baseline immediately and
accept one no-op save. Careful fix: adopt the late baseline only if nothing was typed.

### 3.2 Every hidden route 404s into an unstyled page with no way out

`hooks.server.ts` throws `error(404)` inside `handle`, before the router runs, so SvelteKit
renders its **built-in fallback** — bare "404 | Not found", no navbar, no Home, no theme.
A genuinely missing URL (`/nope-404`) renders our own designed 404 with a Home button.
So the 16 hidden routes are exactly the ones that strand you, which is the opposite of
`MVP.md §4.3`'s "a way home from every page". Fix: redirect hidden paths to `/`, or move the
guard into each route's `+page.server.ts`, or style `src/error.html`.

### 3.3 Players never learn whether they were right

After a question the phone shows **"Results / +760 / Total score: 760"** and nothing else —
no right/wrong, no colour, no rank. Score 0 reads as "+0" with no explanation. Rank appears
only on the final podium. "Basic answer feedback" was explicitly in scope.

### 3.4 There is no frog green

`--primary` is `oklch(0.21 0.006 285.885)` — shadcn's zinc default; `components.json` has no
`theme` key. Every primary control is black (light) / near-white (dark). `CLAUDE.md` says
theme `green` sets it; not true of this tree.

### 3.5 Three strings printed their own key *(fixed, pushed)*

i18next dropped `_plural` at v20; we are on 25. The host lobby with 2+ players printed
`2 play_page.players_waiting_plural` **on the projector**, the host's per-question results
printed it beside every count, and My Quizzes printed `2 words.question_plural` on every card.
`_one` / `_other` were already in `en.json`.
