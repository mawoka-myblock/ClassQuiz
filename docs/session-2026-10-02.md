## 2. Bugs found and fixed

Ordered by how badly they would have bitten.

### Uploads had no server-side limit at all

`POST /api/v1/storage/` passed `size=0` into storage and saved it. The only cap in the
product was Uppy's, in the browser — and that was not applied either, because
`restrictions` is an Uppy **Core** option and was being passed to the Dashboard plugin,
where it appears nowhere in the types. So the picker accepted an SVG and a 2GB file alike
and left the server to answer, and the server did not.

Now 5 MB per image and 1 GiB per account, enforced in three ordered layers: Caddy's
`request_body` at 6 MB, a `Content-Length` guard with 64 KiB of multipart slack, and the
counted bytes in the route. `video/mp4` sits behind a flag that is off.

### `storage_used` was a lifetime counter, not a quota

Nothing anywhere decremented it. It was incremented once per upload by the worker and
never reduced, so the "quota" was a lifetime upload cap. Enforcing the quota — which the
fix above does — would have turned that into a permanent lockout for anyone who had ever
uploaded a gigabyte, however many files they had since deleted.

Deleting an image now releases its bytes, clamped at zero.

### Deleting a quiz left its images behind, forever

Both delete paths matched image keys with a regex describing upstream's old double-key
form. For every modern upload it matched nothing — so a deleted quiz, and every expired
anonymous quiz, left its files in storage permanently and still charged them to the owner.
One reference-counted helper now serves all three paths, cover and background included.

### A closed laptop froze the game for everyone

There was no socket `disconnect` handler. A closed tab stayed in the count that
"everyone has answered" is measured against, so the host sat through every full timer for
the rest of the game. Disconnect now drops the player from the count but keeps their
rejoin key, so a backgrounded phone can still come back.

### A refused answer said "Answer locked in"

`question_not_active` had no listener anywhere in the frontend. An answer the server threw
away still told the player it had counted. Fixed, along with the listener leak beside it —
the component is recreated per question and never released its subscription.

### A teammate could download the answer key

The view page hid correct answers from a non-owner while the Download button beside it,
gated only on being signed in, handed over a spreadsheet containing them. So anyone on the
team could read the answers to a quiz they were about to play. Owner-only since 2 Oct
(D18), 404 rather than 403 so it leaks nothing about the id.

### An over-wide captcha default

`captcha_enabled` defaulted to **true** on `/quiz/start`, where `check_captcha` then raised
`AttributeError` out of `join_game`, because `settings` was `config.py`'s uncalled
`lru_cache` wrapper rather than the settings object. Defaults off now, and refused outright
without a provider key.

### A 500 on the first image upload of any bare-VM deploy

`LocalStorage` never created its `base_path`, and `upload` is a bare `open(..., "wb")`. A
`STORAGE_PATH` pointing somewhere that did not exist yet meant every upload answered 500
with a `FileNotFoundError` in the log and nothing in the response saying why. Docker's bind
mount hides it, which is why nobody hit it. It cost a backend-suite run to find.

### Both lint suites were red, from my own commits

`flake8` had four errors and `eslint` two — unused imports and dead variables left behind
by the uploads and results work. CI runs both. `flake8 .` is 0 now and `eslint .` has 0
errors.

### `e2e/.venv` was one `git add -A` from being committed

Neither gitignored nor excluded from `flake8`, which with a venv in the tree reported about
64,000 errors from other people's packages.

## 3. Things I got wrong

This section exists because every one of these looked like a finding at the time, and the
next person will hit the same shapes.

### I called a feature removal a security fix

I narrowed the Excel export to the owner on 1 Oct, claiming the view page "only offers
Download to an owner". It does not: the `{#if is_owner}` beside it guards **Edit**, and
Download was `disabled={!logged_in}`. I had misread the markup, it broke
`practice.e2e.ts`, and I reverted it. The change was later made for real — but as
François's decision (D18), not as a bug I had found.

**The lesson is in the order:** read the markup, then write the claim. Not the reverse.

### I attributed a test failure to a race, and the measurement disagreed

A full-suite run came back 118/119. I said the failure was the fire-and-forget
`start_game` race fixed earlier in the session, and that converting two more specs closed
it. Then I measured: **the unfixed spec passed 10 out of 10 in isolation.** The
attribution was unsupported and the cause is still unknown — 1 occurrence in 3 full runs.

Note the profile is the *opposite* of the earlier flake, which failed 2 in 10 in isolation.
Sharing a symptom is not sharing a cause. Still open in `TODO.md` with a condition for
closing it.

### I asserted a visitor should not see the answers

D12 hides **which** answer is right, not the options — a visitor needs to see what a quiz
asks to decide whether to play it. My journey test asserted the answer text was absent
entirely and failed against correct behaviour. It now asserts the `sr-only` "Correct" label
is absent for a visitor **and present for the owner on the same page**, so it cannot pass
by the marker being deleted for everybody.

### I corrected my own correction on `svelte-check`

Reported 670/339/331, then corrected to that from an earlier figure, then found both came
from running `svelte-check` twice and counting across two different invocations. A single
run: **1054 total, 229 ours, 825 under `node_modules`.** The original note (~300 ours,
~820 bits-ui) had been right all along.

### Four smaller ones, in the journey specs

- A rejected PIN **clears the field**, so a bad PIN is not a route to an enabled Submit.
  The test assumed otherwise and failed against correct code.
- `getComputedStyle` returns `oklch(...)` verbatim for a token defined in oklch, so
  parsing numbers out of that string yields lightness and chroma, not channels.
- A button with `transition-all` must have its colour **polled**, or it reads back partway
  between two tokens — `rgb(236,236,237)`, which is neither, and looks like an app bug.
- The reset email is **base64** (`MIMEText(..., 'utf-8')` encodes that way) and SMTP is
  **CRLF**, so both a naive regex and a naive MIME split find nothing in a message that
  does contain the link.

### Six user journeys

The suite was organised by **mechanism** — sockets, editor, uploads, exits — and thorough
at it. A journey test fails for a different reason: not "this control is wrong" but **"you
cannot get from here to there."** Each is narrated with `test.step`, so a failure names the
step rather than a line number.

| Spec | The scenario |
| --- | --- |
| `journey-recovery` | Sign up, forget the password, request a reset, **read the real email**, follow the link, set a new one; old password refused, link dead the second time |

#### What the journeys actually found

**Every first-run failure was my assumption, not a product bug.** Nine of them, across six
journeys. The app was right every time, which is the useful result — a journey encodes
what a *user* expects, and where that disagreed with the app, the app won.

| What I assumed | What is true |
| --- | --- |
| A visitor should see no answers | D12 hides **which one is right**; a visitor needs to see what a quiz asks |
| "Answer locked in" appears on tap | It is the screen **after** the timer ends; until then your pick stays held on the tile, as Kahoot does |
| The podium offers "Leave game" | It offers **Home** — once the results are in there is nothing to leave |
| The podium's exit is a button | A link, `href="/my-quizzes"` |
| Log out is a button on settings | A navbar link to `/api/v1/users/logout`, rendered twice |
| A bad PIN leaves the field filled | It clears it, so a bad PIN is no route to an enabled Submit |
| The editor's title is an input | CKEditor `contenteditable`; `toHaveValue` throws "Not an input element" |
| A colour reads back in rgb | `getComputedStyle` returns `oklch(...)` verbatim, and `transition-all` means it must be **polled** or it lands between two tokens |
| The email body is readable text | Base64 (`MIMEText(..., 'utf-8')`), and SMTP is CRLF, so a naive regex **and** a naive MIME split both find nothing |

Each spec carries a comment naming the assumption and the truth, which is the part worth
keeping.

### A mail relay for the e2e stack

`e2e/mailsink.py` — ~90 lines of asyncio SMTP, no new dependency, writing every message to
`e2e/.data/mail/*.eml`.

This is the unlock. `/forgot-password` answers 503 unless `mail_configured` is true, and
the stack had no relay, so **password recovery could not be tested at all** — the one
journey `MVP.md` calls a must-do before sharing.

Hand-rolled rather than aiosmtpd because the backend sends through plain `smtplib` with no
STARTTLS and no AUTH when credentials are blank, so EHLO/MAIL/RCPT/DATA/QUIT is the whole
surface needed.

It buys the parts that actually break in production: the Jinja templates render, and the
reset link is built from `ROOT_ADDRESS` rather than the API's own host. On a split
Netlify/Oracle deploy those are different hostnames, and getting it wrong sends every user
to a host that serves no page. It does **not** prove a real provider accepts the mail.

## 5. Infrastructure

**Oracle halved the Always Free ARM allowance.** `DEPLOY.md` told anyone deploying to
create a 4 OCPU / 24 GB `VM.Standard.A1.Flex` and called it "the whole allowance". Oracle
now states that allowance as **1,500 OCPU hours and 9,000 GB hours a month, or 2 OCPUs and
12 GB** — half what the file said, with no announcement. An over-allowance tenancy is not
trimmed to fit: **every A1 instance in it is disabled and then deleted** after 30 days.

Verified directly from two Oracle documentation pages, because the first search result
quoted the old figures and a secondary source disputes them. `DEPLOY.md` is corrected and
now points at Oracle's page rather than asking anyone to trust a number in a file. Full
analysis, with a dated checklist, is **issue #22**.

The same tier reclaims *idle* instances when CPU p95, network and memory are all under 20%
over seven days — which a quiz tool used once a week meets on all three.
